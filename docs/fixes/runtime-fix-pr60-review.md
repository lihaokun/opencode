# #60 全量审核后的修复

> 2026-11-20：本文保留当时的实现和验证。新摘要的持久化边界、超限用户原文与必保区预算见[保留条数方案](session-fix-summary-retained-count.md)。

## 一、现象与复现

基于 46b40d1f44。再次压缩时文件正文消失，重放后沿用旧文件；历史授权变化仍重读磁盘。后台完成消息使用旧 agent，TERM 被忽略会阻塞取消。grep 的前后文跨页串文件，大窗口和 MCP 错误会绕过截断。独立审查使用两轮真实压缩、本机进程与 rg、公开 SDK schema 复现上述路径。

## 二、根因

原测试大量断言局部形状：仅数恢复块、筛出 match 行、从包含命令标题的字符串寻找 stdout。组件测试之间没有覆盖权限变化、旧块退役、通知失败和取消。CI 运行的是这些同样的断言。

## 三、参考与验收口径

当前 read/skill 的有效许可、agent inbox 的目标会话身份、前台 shell 的有界停止、Truncate 的完整输出文件、rg 真实的行号/文件、运行时 config schema 分别是校验依据。PBT oracle 独立从初始文件、操作序列及真实输出推导。

## 四、修复方案

1. Restoration 依据当前 agent/session 的有效权限静默恢复。只有显式允许的读取/外部目录/skill 可以自动重读，其他项跳过或降级。只识别本功能产生的恢复块；去重只看退役后仍可见的正文，replay 不复制旧恢复块。引用原因有界，正文预算只扣实际可内联项。
2. 后台 shell 沿用有界杀进程机制；通知继承目标当前身份，投递失败隔离于进程结果。修复尾行、同毫秒排序和已结算错误，不把后台输出写进通用截断文件。
3. grep 对真实命中归属前后文；流式跳过深 offset，并界定返回条数和字节；保留可继续的入口，count 越界使用文件单位。容忍 rg 的辅助 bytes 记录。MCP 大错误与成功结果一样受预算保护；摘要为显式全文路径保留位置，截断不破坏 Unicode。
4. 移出 issue74 的临时安装包，同步 OpenAPI 快照，修正与现状冲突的指引及测试代理判定。

## 五、正确性论证

在当前授权下重读；每次恢复完成后校验实际可见的材料及版本。后台任务的进程状态独立于通知。分页按行号、文件和 offset/limit 的 match 区间选择，完整输出仍可检索。发布类型与实际配置验证器使用同一来源。

## 六、测试

将审核中的反例固化为回归，增加状态序列与多文件分页、预算边界、Unicode、结构化错误的性质覆盖。对同一 head 完整运行受影响模块、类型检查、独立复审并回填结果。
